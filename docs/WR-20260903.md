# Stage A / Stage A.5 周报

**日期：** 2026-09-03  
**项目：** `/data/chenyuan/videogrounding/w1m2`  
**实验范围：** Stage A 事件边界诊断、Stage A.5 反事实候选 Oracle 与 GT-free 门控式边界收缩

## 1. 本周结论

本周完成了 Stage A.5 的 P0 协议修正、ActivityNet validation 全量 P1，以及三个 checkpoint 的 P2 Oracle、selector scan 和冻结配置评估。

核心结论如下：

- 收缩候选集合本身是有效的：candidate-set oracle 相对于原始 proposal 集合的 mIoU 上限增益为 `+0.1031`（best-r1）和 `+0.0900`（best-composite/best-r5），且正增益并非只来自极小 GT-width 桶。
- 当前在线评分信号不能可靠识别正确收缩：NLL 与 delta-IoU 的 Spearman 相关接近 0，AUC 接近随机；legacy selector 大量选择有害 trim。
- 完整 selector 网格扫描中，三个 checkpoint 均为 `0/1962` 个配置通过 Stage B gate。最终选择的是“无 gate-passing 配置时 objective 最优、但强制 `STAGE_B_GO=false`”的保守配置。
- 实际冻结 selector 的改动比例仅为 `0.216%`～`0.773%`，性能变化处于零附近；best-composite/best-r5 的 R@5 mIoU 还有小幅且 bootstrap CI 全负的下降。
- 当前不进入 Stage B，不运行 ActivityNet test，不实现 Label Propagation。最终决策：

```ini
STAGE_B_GO=false
```

这里的“候选集合有 Oracle 增益”不能等同于模型已经获得了可部署的边界收缩能力；当前主要问题在候选排序/选择信号，而不是候选生成完全没有覆盖能力。

## 2. Stage A + Stage A.5 工作内容（可直接接在截图后）

在完成截图中列出的事件边界索引和 CPL 推理链路接入后，本周将 Stage A 与 Stage A.5 串成了一条完整的实验链路。Stage A 负责“找到可能的动作边界”，Stage A.5 负责“尝试把 proposal 的边界向内收一点，并检查这样做是否真的更准确”。具体实验包括：

- 在不改变原始 `cpl_lrev` 和 checkpoint 的前提下，使用 ActivityNet C3D、Charades I3D 的事件边界信息辅助推理；
- 对每个原始 proposal 保留一份 `original`，再生成六种向内收缩的候选区间：左侧轻微/明显收缩、右侧轻微/明显收缩、两侧同时轻微/明显收缩；
- 对同一个 query 和 proposal，使用完全相同的 mask 分别测试原始区间和收缩区间，观察收缩后是否仍能重建 query 信息，以及被删掉的边缘区域是否包含重要信息；
- 记录每个候选的重建损失、不同 mask 之间的稳定性、边界置信度和收缩幅度；
- 先做 Oracle 实验：假设有一个“完美选择器”，检查候选集合里是否确实存在比原始 proposal 更接近 GT 的区间；
- 再做实际 selector 实验：只使用不含 GT 的模型信号选择候选，比较收缩前后的 R@1/R@5、mIoU 和 IoU@0.5；
- 对 legacy NLL 选择规则和新的门控式 selector 分别进行 regret、GT-width 分桶、shell contrast、bootstrap 等分析；
- 在三个 ActivityNet checkpoint 上完成全量 validation，使用 3 组固定 mask seed，并检查 features/labels 的样本是否严格对齐。

通俗地说，这组实验分成两步：第一步问“我们生成的收缩边界里有没有好答案”；第二步问“模型自己能不能从这些答案里挑出好答案”。结果表明，候选里确实有好答案，但当前模型使用的重建 NLL、shell contrast 和边界置信度还不能稳定判断哪个边界更接近真实动作边界。因此，Stage A.5 最终采取了非常保守的策略：只有在多个条件同时满足时才收缩，否则保留原始 proposal。

### 2.1 P0 协议修正

本周还修正了正式实验前的协议问题：

- 修复一次性 `weight_grid` 迭代器，确保每个 semantic parent 都遍历完整权重网格；
- selector 配置采用 gate-first 选择规则：有 gate-passing 配置时只能在其中选最优；无 gate-passing 配置时保留 objective 最优配置，但强制 `STAGE_B_GO=false`；
- selected config 增加 `num_scanned_configs`、`num_gate_passing_configs`、`selection_reason` 和 `STAGE_B_GO`；
- 默认拒绝 `partial=true`、Charades test-as-validation 等产物进入正式 oracle、scan 和 evaluate；
- `--allow-partial-smoke` 和 `--allow-test-diagnostic` 只允许诊断运行，并强制 `diagnostic_only=true`、`STAGE_B_GO=false`；
- 增加 partial、Charades test-as-val、GT 泄漏、weight-grid 覆盖和 gate-first 选择测试。

### 5.3 Legacy selector regret：原有 NLL 选择规则不可靠

legacy selector 只用原有 NLL 容忍度选择更短 proposal，结果明显偏向错误收缩：

| checkpoint | changed | helpful | harmful | trim precision | mean delta-IoU | mean regret |
|---|---:|---:|---:|---:|---:|---:|
| best-r1 | `65.665%` | `20.563%` | `27.688%` | `42.62%` | `-0.02104` | `0.08655` |
| best-composite/r5 | `48.495%` | `13.985%` | `22.508%` | `38.32%` | `-0.01992` | `0.07707` |

这里的 helpful/harmful 是相对于原 proposal、以 `±0.01` delta-IoU 为阈值统计。legacy selector 的平均 delta-IoU 为负，且 harmful 比例高于 helpful 比例，说明“重建更容易/损失不升高”不是可靠的边界正确性代理。

### 5.4 NLL 与 shell contrast 判别力

对有效 trim 候选进行反事实 NLL 分析：

| checkpoint | Spearman(delta NLL, delta-IoU) | AUC（`-delta NLL` 判别 helpful trim） |
|---|---:|---:|
| best-r1 | `-0.0690` | `0.4938` |
| best-composite/r5 | `-0.0424` | `0.5170` |

AUC 接近 `0.5`，说明 trim NLL 相对于 original 的变化近似随机，甚至在部分分桶上与正确定位方向相反。shell contrast 也没有形成稳定的定位信号：例如高强度的 `both_strong` 候选在全量候选统计中 harmful 明显多于 helpful，不能把较大的 contrast 直接解释成正确边界。

同时，边界置信度分桶没有证明“置信度越高，trim 越正确”：

- best-r1 的候选 delta-IoU 均值：low `-0.0187`、medium `-0.0325`、high `-0.0352`；
- best-composite/r5 的候选 delta-IoU 均值：low `-0.0262`、medium `-0.0392`、high `-0.0405`。

这说明当前 boundary confidence 更像是边界响应强度，而不是与 GT 对齐的边界正确性概率。

## 6. 当前模型/方法的问题定位

### 6.1 候选生成不是当前第一瓶颈

Oracle 结果显示，许多原 proposal 的 inward trim 中确实存在更接近 GT 的候选，且在 short、medium-short、medium-long、long 四个桶都有正的 candidate-set 上限增益。因此不能简单归因于“事件边界没有生成有用候选”。

### 6.2 Reconstruction NLL 与 localization IoU 目标错位

当前模型的 reconstruction NLL 更容易衡量“保留的片段是否足以重建 query/上下文”，但不等价于“边界是否准确”。它可能偏好：

- 保留容易重建的背景或上下文；
- 去掉真正影响局部化的动作边界；
- 用更短的片段降低表面重建难度；
- 将 mask 下的语言重建稳定性误当成时序边界充分性。

这解释了 NLL AUC 接近随机、legacy selector 平均 delta-IoU 为负，以及 shell contrast 和 boundary confidence 不能稳定预测正确 trim。

### 6.3 当前 selector 处于“两难”状态

- 放宽规则时：legacy selector changed fraction 很高，但 harmful trim 多于 helpful trim，整体 regret 明显；
- 收紧规则时：三个 checkpoint 都没有 gate-passing 配置，最终 changed fraction 低于 `1%`，只能近似回退 baseline。

也就是说，当前 selector 不是简单的阈值未调好，而是缺少一个与边界正确性可靠对齐的 GT-free 评分信号。

### 6.4 checkpoint 对比受到重复模型状态限制

best-composite 和 best-r5 的 SHA256 完全一致，P1/P2 指标也完全一致。因此目前不能从三条 checkpoint 结果得出“三个独立训练状态都验证了同一结论”的强结论；可以确认的是 best-r1 状态与 best-composite/best-r5 这一重复状态均未通过 Stage B gate。

### 6.5 工程质量问题

正式导出过程中出现过：

```text
RuntimeWarning: invalid value encountered in subtract
contrast_values = shell_values - nll_values
```

其原因是无效候选的 `inf - inf`。当前有效性过滤未让它进入正式统计，但应在后续实现中显式避免对非 finite 值做减法，以免 NaN 污染诊断和 selector 输入。

## 8. 后续建议

当前不应进入 Stage B 或 Label Propagation。建议下一步优先做以下研究：

1. 重构 candidate scoring，使其直接针对 query-conditioned temporal localization，而不是只依赖 reconstruction NLL；
2. 重新检查事件边界与 proposal 的匹配方式，验证 boundary score 是否真正对应 proposal 端点误差；
3. 分离“语义充分性”和“边界精确性”两个目标，避免 shell/trim 重建信号单独决定收缩；
4. 在不向在线 selector 泄漏 GT 的前提下，使用离线 GT 只做训练/验证诊断，建立可泛化的 boundary-aware proxy；
5. 修复 `inf - inf` 的 contrast 计算，并补充非 finite 输入的回归测试；
6. 如需正式比较 best-composite 与 best-r5，应先确认 checkpoint 保存/命名流程，生成真正不同的模型状态后再重复 P1/P2。

除非新的候选评分器在完整 validation 上同时通过候选收益、selector gate、GT-width 分桶和 video-cluster bootstrap 门槛，否则保持：

```ini
STAGE_B_GO=false
```
