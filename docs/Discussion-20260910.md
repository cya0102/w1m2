# CPL_LREV 改进方案讨论稿

**日期：2026-09-10**  
**汇报主题：从两篇 Video Captioning 论文出发，分别改进 CPL_LREV 的候选生成与候选排序**

## 一、先用一句话说明当前问题

CPL_LREV 现在的核心做法是：先从视频中生成 5 个候选时间段，再看每个时间段能不能把输入句子重建出来；重建句子的损失越低，就越倾向于认为这个时间段是正确答案。

这个思路的问题是，**“容易把句子说出来”不等于“时间段定位准确”**。

例如，query 是“一个人拿起杯子喝水”。一个较宽的时间段可能同时包含人、杯子、桌子和喝水前后的场景，因此很容易重建这句话，但真正的“喝水”动作只占其中一小段。模型会认为宽区间更可靠，IoU 却不一定更高。

目前实验也支持这一判断：R@5 明显高于 R@1，说明 5 个候选中经常已经存在较好的区间，但模型没有把它排到第一；同时，短事件的表现明显弱于长事件，说明候选生成阶段也存在边界信息损失。

因此，我把问题拆成两个相对独立的部分：

1. **候选生成问题**：短动作和真实边界没有被充分保留下来。
2. **候选排序问题**：好候选可能已经生成，但现有 NLL 排序更喜欢包含大量上下文的宽区间。

下面两个方案分别解决这两个问题。

---

## 二、方案一：QCEC——先把视频整理成连续事件块，再让 query 选择

### 2.1 来源论文讲了什么

第一篇论文是 *Explicit Temporal-Semantic Modeling for Dense Video Captioning via Context-Aware Cross-Modal Interaction*。

它的基本观点很直观：视频不是一堆互相独立的帧，而是由若干连续的小事件组成。与其让模型直接在大量零散帧中寻找事件，不如先把相邻且内容相似的帧整理成连续的“事件块”，再利用文字信息判断哪些事件块与当前描述有关。

论文中有两个关键步骤：

- 先把时间上相邻、视觉上相似的帧聚成连续片段，减少帧级噪声，同时保留片段开始和结束附近的变化。
- 再利用文字语义增强相关片段，抑制与描述无关的片段。

真正值得借鉴的不是某个具体 Transformer，而是这个处理顺序：**先显式整理视频的时间结构，再做文本条件下的选择。**

### 2.2 它对应 CPL_LREV 的什么问题

CPL_LREV 原始视频特征大约有 200 个时间点，但进入主要定位模块前会压缩到约 50 个时间点。这个过程计算方便，却可能把很短的动作压成一个点，甚至完全淹没在邻近场景中。

此外，目前的多个高斯分量可以分别落在不同位置，但最后输出边界时，常直接取最左分量到最右分量形成一个大区间。如果两个分量之间夹着无关内容，最终区间仍会把这段背景包进去。

所以这里有两个具体矛盾：

- 模型在看清边界之前就降低了时间分辨率；
- 模型知道多个位置“有点相关”，却不知道它们是否属于同一个连续事件。

### 2.3 我们准备怎么改

方案名称是 **QCEC：Query-conditioned Coherent Event Clusters，查询条件的连续事件块建模**。

可以把它理解为：在 CPL_LREV 正式生成候选之前，先给视频做一张“事件地图”。

具体流程如下：

1. **在 200 个时间点上找连续事件块。**

   只允许时间上相邻的帧合并。相邻帧内容相近，就归入同一个块；出现明显变化，就形成新的块。这样得到的不是零散 top-k 帧，而是一组有开始、有结束的连续片段。

2. **让 query 判断每个事件块是否相关。**

   把 query 粗略拆成动作、实体和整句，例如“拿起”“杯子”“一个人拿起杯子”。模型分别判断每个事件块是否支持这些信息。这样，同一个镜头切换只有在与 query 有关时才会影响定位。

3. **把事件块信息送给原来的候选生成器。**

   原有 5 个 proposal 和高斯生成方式先不删除，而是增加三个提示：当前位置与 query 的相关度、可能是左边界的概率、可能是右边界的概率。这样改动相对可控，也方便与原模型直接比较。

4. **限制候选跨越明显无关的事件变化。**

   如果一个候选内部跨过了很强的语义变化，而且变化两侧只有一侧与 query 相关，就降低该候选的得分；如果候选边界正好靠近一个可信的事件变化，则给予鼓励。

5. **推理时做很小范围的边界吸附。**

   原模型先给出粗边界，再在附近几个高分辨率时间点内寻找更合理的事件块边缘。这里不是重新搜索整段视频，而是做局部修正，因此风险和开销较低。

### 2.4 为什么它可能有效

这个方案主要改变的是模型“看时间”的方式。

- 对短事件：先在 200 个时间点上保留事件块，再压缩特征，避免短动作在降采样时直接消失。
- 对边界：模型不再只依靠一个共享 width，而是能看到局部事件从哪里开始、在哪里结束。
- 对宽区间：跨越无关事件块会受到惩罚，两个相隔较远的高斯分量不再理所当然地合并。
- 对 query-video 交互：视频变化是否重要由当前 query 决定，而不是所有 query 共用一张背景或变化图。

一个简单类比是：原模型像是先把一本书每四页合成一页，再找某句话发生在哪；QCEC 是先标出各个章节的起止位置，再进行压缩和检索。

### 2.5 与原论文相比，我们的创新在哪里

原论文的目标是 dense video captioning，利用事件聚类和外部文本增强视频表示。我们的任务是单 query 的 temporal grounding，不能直接复制它的句子检索模块。

我们的改造主要有三点：

- 不使用外部句子库，只使用当前 query 的动作、实体和整句信息。
- 事件块不用于生成 caption，而是用于初始化 proposal、限制跨事件区间和微调边界。
- 增加了“内部是否跨越无关语义断点”的连续性判断，这是针对 CPL_LREV 多高斯 outer boundary 问题设计的。

因此，这不是把 caption 模块搬过来，而是把“显式时间结构”重新解释为 grounding 的边界先验。

### 2.6 最小验证实验

第一步不需要大规模改模型，可以做一个 QCEC-lite：

- 主干、5 个 proposals、原有损失和训练轮数全部不变；
- 只在高分辨率特征上计算连续事件块；
- 给原模型增加事件相关度和左右边界提示；
- 推理时只做一次局部边界吸附。

重点观察：

- R@1、R@5 在 IoU 0.3、0.5、0.7 下的变化；
- GT 宽度小于 0.15 的短事件表现；
- 预测区间跨越强语义变化点的比例；
- proposal 平均宽度与相互重叠程度。

如果短事件 mIoU 有明显提升、IoU 0.5/0.7 不下降，并且跨无关变化点的区间变少，就说明“先保留连续事件结构”是有效的。若只改善语言重建或长事件，对短事件没有帮助，则不值得继续增加复杂模块。

### 2.7 主要风险

- 视觉变化不一定是语义边界，例如相机晃动可能造成假变化。
- 有些事件外观变化很小，例如“站着等待”，可能没有明显边界。
- 事件块太少会继续伤害短动作，太多又会接近逐帧建模，增加噪声和计算量。
- 边界提示如果不够可靠，可能把原本正确的粗边界吸到错误位置。

因此，第一阶段应先冻结原候选生成器，只验证事件块作为额外提示是否有价值。

## 三、方案二：BPSE——不再只问“句子能不能重建”，而是同时检查“有没有漏”和“有没有多”

### 3.1 来源论文讲了什么

第二篇论文是 *OwlCap: Harmonizing Motion-Detail for Video Captioning via HMD-270K and Caption Set Equivalence Reward*。

这篇论文指出，评价一条详细 caption 不能只看它和参考句子整体上有多像，还要分别检查两件事：

1. **正确性**：模型说出来的内容是不是都能在参考信息中找到依据，不能凭空多说。
2. **完整性**：参考信息中的关键内容是不是都被模型说到了，不能遗漏。

论文把句子拆成若干最小语义单元，再做双向匹配。只有“没有多说”和“没有漏说”同时满足，caption 才算真正等价。

这个思想对 grounding 很有启发：一个好的时间段也应该同时满足“包含 query 所需的全部证据”和“没有包含太多 query 无法解释的事件”。

### 3.2 它对应 CPL_LREV 的什么问题

当前 CPL_LREV 更接近只问一个问题：**从这个候选时间段出发，能不能把 query 重建出来？**

这会产生两类错误：

- **过窄区间**：只拍到人和杯子，没有完整拍到“拿起并喝水”的动作，但仍可能猜出句子。
- **过宽区间**：完整包含喝水动作，同时还包含坐下、说话等其他事件，因为信息更多，重建 NLL 反而更低。

此外，训练时 hard-min 只奖励当前 NLL 最低的一个候选。这个候选一旦因为语言捷径或宽区间占优，后续训练就会继续强化它，形成自我确认。

而 R@5 远高于 R@1 说明：很多时候不是没有好候选，而是当前评分方式没有选对。

### 3.3 我们准备怎么改

方案名称是 **BPSE：Bidirectional Proposal-Set Equivalence，双向语义等价的候选排序**。

核心是为每个 proposal 计算两个容易解释的分数。

#### 分数一：完整性——query 要求的信息是否都在区间里

先把 query 拆成少量必要单元，例如：

> “一个人拿起杯子喝水”  
> → 人、拿起、杯子、喝水

模型分别检查区间内是否存在支持这些单元的视觉证据。如果只看到了“人”和“杯子”，却没有完整动作，完整性分数就会偏低。

这里不是要求每个词都单独对应一帧，而是把动作、实体、属性和关系作为语义短语进行匹配，避免把冠词、介词等无关词也纳入判断。

#### 分数二：纯净性——区间里的主要内容是否都能由 query 解释

再反过来检查区间：区间中出现的主要事件，是不是都和 query 有关。

如果一个宽候选除了“喝水”，还包含了明显的“坐下”和“与人交谈”，这些额外事件无法被 query 解释，纯净性就会下降。这样，宽区间不再因为包含更多上下文而天然占优。

#### 两个方向联合打分

最终质量分数同时依赖完整性和纯净性：

- 只高完整性、低纯净性，通常说明区间太宽；
- 只高纯净性、低完整性，通常说明区间太窄；
- 两者都高，才更接近完整而紧致的目标区间。

可以先使用简单的调和平均，后续再训练一个很小的质量预测头。推理时直接使用这个质量分数给 5 个 proposals 排序，不再完全依赖 raw NLL。

### 3.4 如何训练这个排序器

弱监督场景下没有真实边界可直接告诉模型哪个 proposal 更好，因此我们从现有候选构造一组局部变体：

- 左右稍微扩大；
- 左右稍微收缩；
- 整体向左或向右移动。

如果某个变体在不损失 query 完整性的情况下去掉了无关内容，就把它作为相对更好的候选；如果扩宽后加入了无法解释的事件，就把它作为相对更差的候选。

为降低伪标签错误，只使用双向分数差异足够明显的候选对。训练时冻结用于产生伪比较的分数，避免模型一边改特征、一边修改自己的答案标准。

原有 reconstruction loss 可以保留，继续保证候选具有基本语义可识别性，但它不再单独决定 winner。

### 3.5 为什么它可能有效

这个方案主要改变的是模型“如何判断一个候选好不好”。

- 它直接区分了漏掉目标内容和包含无关背景两种错误。
- 它以 query 的关键语义为单位，而不是让常见词和语言流畅度主导整个句子的 NLL。
- 它训练和推理都使用同一个质量头，避免当前 LREV 在训练中使用、推理权重却为零的问题。
- 它不要求先提高 R@5；即使候选集合完全不变，也可能直接把已有的好候选排到第一，从而缩小 R@5 与 R@1 的差距。

一个简单类比是：原模型给论文打分时只看“能不能写出摘要”；BPSE 还会逐项检查“关键贡献有没有漏”和“有没有把别人的工作也写进来”。

### 3.6 与原论文相比，我们的创新在哪里

OwlCap 的双向匹配发生在“生成 caption”和“参考 caption”之间。我们的双向匹配发生在“query 语义单元”和“候选区间视觉事件”之间。

对应关系是：

- 原论文的“参考内容是否都被说到” → query 的关键动作、实体、关系是否都在区间中得到支持；
- 原论文的“生成内容是否都有依据” → 区间中的显著事件是否都能被 query 解释；
- 原论文使用 GRPO 优化大模型 → 我们使用轻量的候选内 pairwise/listwise 排序，不需要语言模型强化学习。

因此，借鉴的是“双向集合等价”的评价原则，而不是复制 caption reward。

### 3.7 最小验证实验

BPSE 很适合先做冻结模型的低成本实验：

- 冻结整个 CPL_LREV；
- 缓存每个样本的 5 个 proposals、帧特征和 query 特征；
- 只用简单规则抽取动词和名词；
- 训练一个两层 MLP 质量头；
- proposal generator 和原有损失全部不改。

对比以下排序方法：

1. raw reconstruction NLL；
2. 当前 semantic vote；
3. 只看完整性；
4. 只看纯净性；
5. 完整 BPSE。

重点看：

- 在 R@5 基本不变的情况下，R@1@0.5 是否提升；
- R@1 与 R@5 的差距是否缩小；
- 预测区间平均宽度是否更接近 GT，而不是一味缩短；
- 完整性与纯净性分别和真实 IoU 有多大相关性。

如果 proposal 集合不变，BPSE 仍能让 R@1@0.5 提升约 2 个百分点，并且不是靠所有区间统一缩短取得，就说明当前主要瓶颈确实在排序。如果 R@1 不变，或者只提高短区间偏好却降低 recall，则应重新检查双向分数的定义。

### 3.8 主要风险

- query 自动拆分可能出错，尤其是复杂短语、同义词和隐含主语。
- 现有 C3D 特征可能无法识别很细的实体或动作，导致完整性判断不可靠。
- 区间中的“显著变化”不一定是独立事件，相机运动可能被误判成额外内容。
- 如果双向分数仍完全依赖当前模型的 feature，它与原模型可能共享偏差，因此要使用停止梯度、困难候选和视频打乱测试检查是否真的利用了视觉。

## 四、两个方案的区别与关系

| 对比项 | QCEC | BPSE |
|---|---|---|
| 主要解决阶段 | 候选生成和边界形成 | 候选评分和排序 |
| 主要问题 | 短事件丢失、边界模糊、outer hull 跨背景 | NLL 偏爱宽区间、hard-min 自确认、R@1 排序差 |
| 核心直觉 | 先把视频整理成连续事件块 | 同时检查“该有的有没有”和“不该有的多不多” |
| 对现有模型改动 | 中等，需要增加高分辨率事件结构 | 较小，可先冻结模型训练质量头 |
| 最直接的预期收益 | 短事件 R@5、IoU 0.7、边界质量 | R@1、候选质量与 IoU 的相关性 |
| 主要风险 | 事件变化点不等于语义边界 | query 单元和显著事件判断存在伪标签偏差 |

两个方案不是相互替代关系：QCEC 负责让 5 个候选本身更好，BPSE 负责从候选中选出最好的一段。它们可以独立验证；若各自有效，后续也可以串联为：

> 高分辨率事件块生成更可靠候选 → 双向完整性/纯净性质量头完成排序。

但初期不建议直接联合训练，否则无法判断收益来自候选生成还是排序。

## 五、建议的实验顺序

建议先做 **BPSE-lite**，再做 **QCEC-lite**。

理由是：

1. 当前 R@5 与 R@1 差距大，先冻结 proposal set 做 BPSE，可以最快判断主要瓶颈是否真的是排序。
2. BPSE 只需缓存现有特征并训练小质量头，实验成本低，失败后也容易定位原因。
3. 若 BPSE 明显改善 R@1，但短事件 R@5 仍低，再引入 QCEC，针对候选生成和时间分辨率继续改进。
4. 若 BPSE 几乎无效，而 QCEC-lite 能提高短事件和高 IoU 指标，则说明当前瓶颈更靠前，主要在 proposal 结构而不是 ranker。

建议将第一轮实验形成一个清晰的诊断矩阵：

| 实验结果 | 说明 | 下一步 |
|---|---|---|
| BPSE 提升 R@1，R@5 不变 | 候选已有，排序是主要问题 | 完善独立质量头与困难候选训练 |
| QCEC 提升 R@5，尤其短事件 | 候选覆盖和边界结构是主要问题 | 联合训练事件块与 proposal generator |
| 两者都有效 | 生成与排序均有独立瓶颈 | 分阶段训练后再尝试串联 |
| 两者都无效 | 当前视觉特征或 query-frame 对齐更基础地受限 | 优先检查 C3D/GloVe 表征与视觉依赖问题 |

## 六、向导师汇报时可概括为三句话

1. **当前 CPL_LREV 用句子重建难度代替区间质量，因此会偏好信息更多的宽区间，也无法稳定把 R@5 中的好候选排到第一。**
2. **QCEC 从候选生成端入手，在降采样前保留连续事件结构，并用 query 判断哪些变化是真正的目标边界。**
3. **BPSE 从候选排序端入手，同时检查 query 语义是否完整、区间内容是否纯净，用与定位质量更一致的标准替换单一 NLL 排序。**
